# 我写出了第一只"蜘蛛"：Python 爬虫 Phase 2 实录 🐝

地基（Phase 0）和数据处理（Phase 1）打完后，我进了最让人兴奋、也**最快能变现**的一关——**爬虫（Phase 2）**。

buddy 当时一句话点透它的定位：**爬虫 = 去那些"没有现成大门（API）"的网站，把数据搬出来。** 它是我们这条"从 Python 学到独立接单"路线里，离赚钱最近的一步（比价、获客名单、市场调研都能用上）。

这一关我是从一只练手小蜘蛛开始的，一路打到了"合规 + 反爬 + 动态页面"的全套本事。下面按真实学到的顺序讲。

## 一、爬虫的本质：两半

buddy 用第一性原理拆得很干净：**爬虫不是黑客技术，它就是"用程序模拟你手动浏览网页 + 把看到的信息抄下来"**。人点鼠标看网页，程序发请求拿网页；人用眼睛找信息，程序用规则找信息。

所以它永远是**两半**：

```
① 要数据：程序敲网站的门，说"给我这一页" → 网站回你一大段 HTML
② 读数据：从这堆 HTML 里，按标签/类把你要的字段揪出来
```

> 类比很巧：**点外卖**。① 下单（发请求）→ ② 商家把餐送到（响应 HTML）→ ③ 你拆开包装，只夹想吃的菜（解析抽取）。爬虫就是这三步的自动化。

我自己的费曼理解（原话）：**"爬虫就是你去废品站，想要什么就拿什么。"** —— 方向对，但 buddy 立刻 push back 了：网站上的数据是**别人家的资产，不是扔在地上的破烂**。"废品站"暗示随便拿，这会踩合规红线。准确说法应该是：**敲门可以，破门不行；礼貌 + 守法是底线。**

## 二、第一只蜘蛛：requests + BeautifulSoup

练手目标是 `quotes.toscrape.com` —— 一个**专门开放给学习者练**的网站。故意选它，因为爬虫第一条铁律就是"先看规矩"。

核心就四行：

```python
resp = requests.get(url, timeout=10)          # ① 敲门要点这一页
soup = BeautifulSoup(resp.text, "html.parser") # ② 把 HTML 变成可搜索的"树"
quotes = soup.select("div.quote")              # ③ 找出所有"名言块"
q.select_one("span.text").get_text(strip=True) # ④ 在块里精确取字段
```

几个必须记住的点：

- `resp.status_code` → **200 成功 / 404 页面没了 / 403 被拒绝**，爬虫第一眼就看它。
- `resp.text` → 网站回给你的**原始 HTML 文本**（一堆带标签的字符串）。
- `BeautifulSoup(...)` → 把死文本变成**能按标签查的树**。
- `select("div.quote")` 找一批，`select_one(...)` 精确定位一个。

**费曼关卡的灵魂一问**：为什么爬虫要分成"要数据"和"读数据"两半？`resp.text` 和 `soup` 各是什么、差在哪？—— 答不上来就不许进下一关。**`resp.text` 是"生肉"（原版 HTML），`soup` 是"切好的菜"（结构化可查的树）**，前者给程序看不懂，后者才方便按规则抠字段。

## 三、翻页 + 批量 + 存 CSV

单页会爬了，下一步是**加腿**：找"下一页"链接、循环翻页、抓 100 条、存成 CSV。这里刚好把 Phase 1 学的 pandas 用上了：

```python
df = pd.DataFrame(数据列表)
df.to_csv("quotes.csv", index=False, encoding="utf-8-sig")
```

`encoding="utf-8-sig"` 是为了让 Excel 打开中文不乱码（经典坑）。**为什么用"找 Next 链接"而不是写死 1~10 页？** 因为页码是网站说了算的，链接跟着走才不怕它改结构。

## 四、2.5 反爬基础：四道防线

buddy 把反爬讲成"去别人店门口拿传单"：你举着"我是机器人"的牌子（默认 UA）、一秒冲进去 50 次（没延时）、门没开就走（不重试）——店家不拦你才怪。

| 技术 | 一句话 | 防的是什么 |
|------|--------|-----------|
| **UA** | 把"机器人身份证"换成"浏览器身份证" | 网站一看 `python-requests` 就直接拦 |
| **延时** | 每翻一页 `sleep` 一下 | 一秒发几十请求 → 被限流/封 IP |
| **重试** | 失败最多试 3 次，中间歇 2 秒 | 网络一抖就崩，白跑 |
| **代理** | 换 IP 出去（可选） | 单一 IP 被打标/封禁 |

**两个让我印象深的升级：**

1. **随机延时 > 固定延时**。固定 `sleep(1.0)` 等于每 1.000 秒准时迈一步，那种"纹丝不动的周期性"本身就是"你是机器人"的指纹。改成 `time.sleep(random.uniform(1, 3))`，间隔不规则才像真人。
2. **重试 + 退避**：用 `for attempt in range(1, MAX_RETRY+1)` 包住请求，失败就打印警告、`sleep(2)` 再试，连试 3 次才主动抛错放弃——**宁可明明白白告诉你"这页真抓不到"，也不偷偷给你一份缺数据的 CSV**。

> 一句话记牢：**任何"太规律"的行为都是指纹**。延时、请求参数、点击坐标……全可以用随机化打散。

## 五、2.6 合规底线：红线比技术重要

技术解决"能不能爬"，**合规解决"该不该爬"**。这关比技术还重要——踩线可能封号、吃官司、甚至违法。三条铁律：

1. **看 `robots.txt`**（网站的门禁告示）：在域名后直接加 `/robots.txt`，看到 `Disallow` 就别去。练手站默认开放，真站得先瞄一眼。
2. **控制频率 + 留身份**：延时就是这层的技术实现；真做项目可以在 UA 里留联系方式，透明比偷偷摸摸稳。
3. **不碰隐私、不侵权**：**绝不爬个人信息**（手机号、邮箱、身份证、住址）——这违反《个人信息保护法》/GDPR，是真会罚款坐牢的红线。记住：**公开 ≠ 可随意滥用**。

buddy 还给了我一套**专业应对框架**（这才是值钱的部分）：如果客户让你爬"某招聘网站所有求职者的手机号"——

> **判断**：手机号属个人敏感信息，违法。**回应客户**：① 明确拒绝（"涉及隐私，违法"）；② 解释风险（不是懒，是帮你避坑）；③ 给合规替代（"用公开的岗位统计/薪资区间？或你有用户授权？"）。**拒绝不是终点，把客户从红线边拉回白区，才是专业度。**

## 六、2.7 JS 动态加载：标准三步走

有些网页内容不是写死在 HTML 里的，而是**浏览器用 JavaScript 现拉的**。你用 `requests` 拿到的 HTML 里根本没有数据——因为它们是后来才加载的。

buddy 给了一条"标准流水线"，**优先用轻的**：

| 步 | 动作 | 结果 |
|----|------|------|
| **① 先试 requests** | `requests` + `BeautifulSoup` 抓 | 内容齐全 → 完事，**根本不用 Playwright** |
| **② 空了？找后台接口** | F12 → Network → 看 XHR/fetch，找到它吐 JSON 的接口地址，`requests` 直连它 | 拿到数据，轻又快 |
| **③ 还不行？上 Playwright** | 真开浏览器渲染 | 兜底层，最重 |

**为什么 ② 优先于 ③？** 数据本就是网站从接口拉来的——你直接去接口拿，等于跳过了"等 JS 搬家具"，又轻又稳；开浏览器又是下载内核又是渲染，又慢又耗资源。

（代价提醒：Playwright 要额外下载浏览器内核，国内有时慢/被墙，需设 `PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright` 镜像。）

## 七、真实踩坑两连

1. **pip 装包报 `Failed to resolve 'pypi.org'`**：病根不是包名错，是**国内网络连不上 PyPI**（DNS 解析失败）。下面那句"找不到版本"是连锁反应，最会骗人——**先看第一行报错**。解法：换国内镜像 `py -m pip install requests beautifulsoup4 -i https://pypi.tuna.tsinghua.edu.cn/simple`，或一劳永逸设默认源。
2. **顺序铁律**：必须先 `pip install` 成功，再 `py 脚本.py`。包没装就跑，直接 `No module named 'requests'`。

## 小结：爬虫是"自己动手丰衣足食"的第一桶金

把 Phase 2 串起来：

```
第一只蜘蛛(requests+BS) → 翻页批量存CSV → 反爬四道防线(UA/延时/重试/代理)
→ 合规红线(robots/隐私) → JS动态三步走(接口优先/Playwright兜底)
```

它把 Phase 0 的地基（请求会超时要用 try/except 兜底、文件会读写）和 Phase 1 的数据处理（存成 DataFrame 接着分析）全串了起来——**爬虫负责"把数据弄到手"，pandas 负责"把数据处理好"**，俩人一前一后，正好凑成一条完整的数据流水线。
