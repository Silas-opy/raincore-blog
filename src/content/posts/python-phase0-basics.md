# 我的 Python 入门地基：虚拟环境、文件、异常处理与读代码 🐝

很多人学 Python 一上来就急着写爬虫、搞数据分析，结果环境一团乱、报错看不懂、别人代码读不进去。我这个阶段（Phase 0）刻意没急着冲业务，而是先把**地基**打牢——四块砖：虚拟环境、文件读写、异常处理、读代码的方法。

这几块看起来不起眼，但就像盖房子先打地基：地基不牢，后面盖得越高塌得越狠。下面用我自己的理解讲一遍。

## 一、venv 虚拟环境：给每个项目一个"独立房间"

### 用大白话讲

你电脑上装 Python 包，默认是"全局装"——所有项目共享同一堆包。这就像**全家共用一个衣柜**：你妈的裙子、你爸的西装、你的 T 恤全挂一起。

问题来了：项目 A 需要某个包的第 1 版，项目 B 需要第 2 版，它们挤在同一个衣柜里就打架了。更惨的是，你升级了某个包给项目 B，结果项目 A 直接崩了——你都不知道为什么。

`venv` 干的事，就是**给每个项目单独隔出一个衣柜**。项目 A 一个房间、项目 B 一个房间，互不影响。你在这个房间里装什么、卸什么，都不会波及别的房间。

### 我的理解 & 踩坑

- 我一开始图省事，想"全局装多方便"。buddy 直接 push back 了——全局装就像不分类的衣柜，迟早乱到找不到衣服。
- 常用动作就三句口诀：
  - 建房间：`python -m venv 房间名`
  - 进房间（Windows）：`房间名\Scripts\activate`
  - 在房间里装包：`pip install 包名`
- 进房间后，命令行前面会多一个 `(房间名)` 的标记，看到它你就知道"我现在在这个房间的地盘上"。

> 一句话：虚拟环境不是"高级技巧"，是"基本卫生"。每个项目开一个，能省掉 90% 的"我明明装了为什么找不到"的玄学问题。

## 二、文件读写：和电脑里的"文档"对话

### 用大白话讲

程序跑起来，数据往往存在文件里（txt、csv、json……）。"读文件"就是**打开文档看内容**，"写文件"就是**往文档里记东西**。

最关键的礼仪是：**看完要关门**。你进了别人房间不关门，别人进出都不方便，甚至会出乱子。代码里也一样——打开文件不关，可能别的程序打不开它，数据也可能没真正写进去（还在缓冲区里没刷盘）。

Python 有个贴心的写法 `with open(...) as f:`，它相当于一个**自动关门管家**：你写代码的时候只管在里面读/写，一出这个代码块，它自动帮你把门关好。比手动 `f.close()` 省心，也不会忘。

### 我的理解 & 踩坑

- 我之前手写 `open` 然后忘了 `close`，buddy 说"你这是进房间不关门"。这句话我记得特别牢。
- 用 `with` 之后基本不再操心关门的事，代码也更短。
- 读和写是两个模式：`'r'` 读、`'w'` 写（会清空原内容！）、`'a'` 追加。第一次我把 `'w'` 当 `'a'` 用，差点把文件清空，吓出一身冷汗——**写模式会覆盖，追加模式才是在末尾加**。

## 三、try/except 异常处理：给程序买份"保险"

### 用大白话讲

程序跑着跑着可能撞上意外：文件不存在、网络断了、除数是 0……这些"意外"会让程序"啪"地崩掉。

`try/except` 的逻辑很像**买保险**：你把"可能出事的代码"放进 `try`（试试看），真出事了就跳到 `except`（备用方案兜底），程序不会直接死给你看，而是优雅地走另一条路。

关键点是**别一网打尽**。如果你写 `except:` 啥异常都接，那连你代码本身的 bug 也会被掩盖，调试时一脸懵。正确做法是**只接你预期会出的那种异常**（比如 `except FileNotFoundError:`），其他的让它暴露出来——因为那可能是你真写错了。

### 我的理解 & 踩坑

- 我最早的理解是"用 try 包住所有代码就稳了"。buddy 纠正：try 不是万能胶，乱用会把真 bug 藏起来。
- 判断标准就一句：**你预判这里可能出什么具体的意外，就接那种意外**；不确定的，别接，让它报错给你看。
- `else` 和 `finally` 也很有用：`else` 是"没事才执行"，`finally` 是"无论出没出事都执行"（比如无论成功失败都要关门/关连接）。

## 四、读代码的方法：拿到陌生代码先别慌

### 用大白话讲

学编程逃不开一件事：**读别人的代码**。一开始我看一大坨代码就头大，像拿到一本没目录的外文小说。

buddy 教我的思路是：**先骨架，后血肉**。拿到代码先别钻细节，先看三样东西——

1. **入口在哪**：从哪个文件、哪一行开始跑？（Python 常看有没有 `if __name__ == "__main__":`）
2. **它依赖谁**：开头 `import` 了什么？这告诉你它用了哪些工具。
3. **主流程怎么走**：函数之间谁调用谁，数据从哪进、从哪出。

像看一棵树的**主干**，先认清楚，再一片片看叶子（具体实现）。

### 我的理解 & 踩坑

- 我以前习惯从上往下一行行读，读到一半就丢了主线。改成"先找入口、看 import、画调用关系"之后，读代码的恐惧感少了一大半。
- 遇到不懂的函数，**先猜它的"职责"（它是干嘛的），再去验证**，比逐行抠实现高效得多。

## 小结：地基打牢，后面才跑得稳

这四块（虚拟环境 / 文件读写 / 异常处理 / 读代码）单独看都不难，但它们是后面所有"大工程"的零件。地基不牢，爬得越高越危险。

下一阶段（Phase 1）我就用这些零件去拼**数据处理全链**——加载、清洗、筛选、聚合、合并、可视化，那才叫真刀真枪上业务。

学编程这件事，慢就是快。先把地基夯实在，比急着冲上线重要得多。🐝
